本次是有限范围的源码审查、依赖公告核对和本机浏览器操作检查，不是完整渗透测试、安全认证或“无漏洞保证”。没有提交真实订单，没有尝试读取系统敏感文件，没有测试第三方服务或公网基础设施。

## 2. 安全及可信度：上线前必须处理

### S01｜正式核验尚不存在（上线阻断）

**已确认：** src/VerifyPage.tsx:9、:43、:61 将一组演示娃证和订单写在前端，以本地字符串比较返回“核验通过”。浏览器实测提交演示数据后，没有发起核验 API 请求。

**影响：** 这只能展示界面流程，不能验证真实客户订单、发行档案或实体真伪。“正式发行 · 有效”等结果是演示内容，不能作为正式凭证。

**建议：**
- 未接入真实服务之前，所有核验入口、表单和成功页统一标明演示，不接收真实订单。当前只修正了本次截图对应的新入口提示，其他文案尚未改动。
- 正式版本在服务端校验娃证与订单关系，结果只返回必要字段；浏览器不保存全量订单映射或有效答案。
- 定义发行、撤销、补证、异常核验等状态，并有人工复核路径。
- “档案匹配”不等于“手中的实物一定为真”或“当前持有人有所有权”；凭证可能被复制。若需更强实体防伪，应另设计一次性激活/防拆凭证等实体关联机制，不能只靠结果页截图。

### S02｜限流仅为前端演示（上线阻断）

**已确认：** src/VerifyPage.tsx:24、:49、:79 使用组件状态计数，reset 会将次数清零。实测连续三次虚构错配后显示“查询暂缓”，点击“重新开始演示”（键盘操作）后，可立即再次通过演示查询。

**影响：** 不能抵御真实核验接口的枚举与批量尝试；刷新或重开也不能构成可靠访问限制。当前没有真实接口，因此这不是已证实的数据泄露。

**建议：** 正式服务实施服务端限流和审计，组合请求来源及目标凭证等维度；返回统一错误，限制输入长度，设置超时及异常告警。避免仅按娃证锁死造成他人恶意锁定。API 的传输、安全响应、限流和服务端访问控制可参考 [OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。

### S03｜开发工具存在已公告漏洞（高优先级）

npm audit 本次返回 **6 个受影响依赖包：5 高危、1 低危**。这是依赖包级告警数量，不等同于 6 条已经可以攻击本站的漏洞。

| 包 | 本地版本 | 报告等级 | 当前主要关联环境 |
| --- | --- | --- | --- |
| vite | 6.4.1 | 高 | 开发服务器 |
| browserslist | 4.28.1 | 高 | 构建工具链 |
| nanoid | 3.3.11 | 高 | 间接依赖，需追踪调用条件 |
| picomatch | 4.0.3 | 高 | 文件匹配/构建工具链 |
| postcss | 8.5.6 | 高 | CSS 构建处理 |
| @babel/core | 7.29.0 | 低 | 编译工具链 |

**最贴近本项目的风险：**
- package.json:7 的默认 dev 命令使用 --host=0.0.0.0；本机为 Windows。
- Vite 6.4.1 落在开发服务器 WebSocket 文件读取问题的受影响范围。是否可被远程利用取决于开发服务能否被访问等条件。[Vite 官方公告](https://github.com/vitejs/vite/security/advisories/GHSA-p9ff-h696-f583)
- 同时落在 Windows 路径变体绕过文件拒绝规则的受影响范围；该公告的 6.x 修复版为 6.4.3。[Vite 官方公告](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff)

**建议：** 升级到兼容且已修复的版本、更新锁文件后重新构建与审计。不要把 Vite 开发服务器当正式服务器公开。需兼顾团队局域网预览需求，再决定是否修改默认监听设置。

本次检查使用的预览服务只监听 127.0.0.1，没有更改原 dev 命令，也没有尝试利用这些漏洞。其他构建依赖告警必须核对不可信输入等触发条件；纯静态成品不等于把整个构建工具链暴露给访客。

### S04｜前端注入密钥的配置隐患（条件性风险）

**源码证据：** vite.config.ts:7 读取环境变量；:11 配置将 GEMINI_API_KEY 替换到前端表达式。

当前活跃页面没有发现对该表达式的使用，常见密钥/私钥模式扫描未发现匹配；因此**没有证据表明真实密钥已经泄露**。但未来一旦引用该表达式，构建值可能进入可下载脚本。建议移除无用途的前端密钥注入配置，真实服务密钥只放服务端。简单字符串扫描不能排除所有秘密信息。

### S05｜隐私与安全文案超出已实现能力（高优先级）

src/VerifyPage.tsx:111、:173、:199 中出现“正式系统仅保存订单号的加密校验值”“正式发行 · 有效”“SSL · PRIVATE · OFFICIAL”。当前没有后端可验证保存方式，本地是 HTTP。

建议将尚未实现的说法改成明确的演示说明；正式上线前落实数据最小化、保留与删除期限、日志脱敏、密钥管理和隐私说明。不把普通摘要直接等同于充分保护，订单关联值的保护方式应按实际威胁模型设计。

### S06｜生产环境安全尚未验证（不是已确认漏洞）

本地响应未见 CSP/HSTS；vercel.json 和 public/_redirects 仅定义 SPA 重写，没有配置这些响应头。生产平台可能在其他位置提供，因此不能据此认定正式站已缺失安全配置。

正式上线需验证：HTTPS、合适的安全响应头、防嵌套策略、敏感响应不缓存、数据库与后台权限、管理账户保护、备份恢复、告警、审计、文件上传安全。当前没有后台/API/上传接口可供检查，不能宣称这些功能已安全，也不能把未存在的接口写成 SQL 注入或上传漏洞。

## 4. 性能与工程质量

- npm run lint：失败，检测到 24 条 TypeScript 错误。包含旧作品集缺失 react-router-dom/lucide-react、React 类型缺失，以及 FlowerGodsExperience 中的类型错误。
- 目前 build 脚本只调用 Vite，不会因上述类型错误自动阻止发布。

建议先确认旧作品集是否还需保留运行；可独立归档，而不是盲目给当前品牌站安装全部旧依赖。为实际运行代码补齐 React 类型、修复类型错误，并建立“类型检查 + 构建 + 关键交互检查”的交付门槛。

### 资源体积与公开目录

- 图片目录共 889 张，约 291.35 MiB。
- 其中历史作品集素材 876 张，约 280.01 MiB，当前品牌页面未直接引用。
- public 内容会被复制进 dist；未显示在页面并不代表不公开，也不代表有权限限制。发布前应检查旧图是否允许公开，另行归档。

## 6. 建议实施顺序

1. **先解决可信度和高风险：** 全站标清演示、升级受影响工具链、去掉无用密钥注入、修复核验按钮遮挡。
2. **再落实正式核验：** 明确娃证/订单数据来源、服务端校验、限流、管理权限、审计与异常复核。
3. **素材与运营：** 按《素材尺寸与补齐清单》拍摄，接入官方图集与返图管理，核实授权。
4. **整体完善：** 路由和 404、品牌区排版、图片放大与键盘行为、字体性能、分享、购买/售后渠道。

需要品牌提供的信息：正式核验数据由谁维护、官方店铺/售后地址、实体素材是否已拍摄、返图授权方式、未来后台维护人员。没有这些信息时，不应自行编造链接、客户数据或“已接入”的服务。

本次所有旧素材均保留；没有将当前演示站发布到公网。
