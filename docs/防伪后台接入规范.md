# 防伪后台接入规范

当前 `/verify` 支持演示与正式两种模式：未配置接口时只使用虚构样例；配置 HTTPS 接口后才显示正式输入框。部署步骤见 `backend/cloudbase/README.md`。

## 查询接口

- 业务查询仅接受 `POST`，字段为 `certificate` 与 `order`；`GET` 仅用于健康检查。
- 两个编号都应在服务端规范化、校验长度与字符范围；浏览器端校验不能替代服务端校验。
- 响应只返回首次通过、重复通过、未匹配、停用、作废或限流状态，不得返回其他客户、完整订单或内部备注。
- 正式地址通过 `VITE_VERIFICATION_API_URL` 接入，开发和生产使用不同环境变量。

## 数据与权限

- 数据库保存娃证编号、订单号的不可逆索引，不在日志中记录原始查询值。
- 后台分为导入、复核和只读角色；所有新增、修改与导出都记录操作人和时间。
- 导入前校验重复娃证、重复订单、必填字段和发行状态；错误行单独返回，不部分静默覆盖。
- 数据库启用加密、每日备份和恢复演练；备份与生产账号分离。

## 防滥用

- 当前函数按不可逆 IP 索引限速；正式运营后可再增加网关级限流与告警。
- 对异常批量查询、遍历编号与重复撞库产生告警。
- 对外错误文案保持模糊，不泄露“娃证存在但订单错误”等可枚举信息。

## 正式接入仍需提供

- 一份脱敏娃证/订单样表及字段解释。
- 已确定腾讯云 CloudBase（上海）与 PostgreSQL。
- 客服复核渠道、保存期限和运营主体信息。
